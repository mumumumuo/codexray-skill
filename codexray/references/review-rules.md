# Phase 3 复核规则（误报过滤 / 去重 / 定级复核 / 攻击链）

Phase 3 是 Phase 2 七个域 findings 的**复核者，不是新的产出者**。必须按顺序做五件事，不得跳过：

1. **误报过滤** —— 逐个 finding 对照该漏洞类型的全部必要条件，缺任一条即标误报
2. **跨域去重** —— 同一漏洞被多个域报告时合并
3. **定级复核** —— 重新判断每个最终 finding 的严重等级与 `severity_reason`，补全 `expected_result`
4. **覆盖缺口审查** —— 对比 Phase 1 攻击面与 Phase 2 实际覆盖
5. **组合漏洞链分析** —— 识别多个独立漏洞如何组合成完整攻击链

## 核心原则（极其重要）

允许的操作（且仅允许这些）：

- **keep** —— 保留某 finding，可调整 severity / confidence（改卡片 `data-sev` / `data-confidence`，补 sev-tag 文本与疑似标签）
- **drop** —— 标记为误报（卡片移到误报视图，见「误报视图写法」）
- **merge** —— 多个重复 finding 合并成一个（保留最详细那条，其余删除；call_chain 不同视角可合并）

**严禁**：

- ❌ 补全 / 重写 POC / evidence / description / fix_suggestion / code_trace 字段（这些是 Phase 2 子代理的职责，复核只决策 keep/drop/merge 与定级）
- ❌ 新增 Phase 2 没有提交过的 finding
- ❌ 把脚本类 POC 改写为 Python

如果认为某 finding 的 POC 不完整或描述不准，**不要修改它** —— keep（按原样保留）或 drop（标误报）。

## 1. 误报过滤（逐类型必要条件审查）

每个 finding 必须同时满足该漏洞类型的全部必要条件才是真漏洞。缺少任一条件即误报。

### 通用前置条件（所有漏洞类型）

1. **路由可达**：POC 中的路由在项目路由注册中真实存在，HTTP 方法和路径匹配
2. **代码可达**：漏洞代码不在死代码分支、被注释代码、`//TODO` 未实现逻辑或测试文件中
3. **非安全模式**：框架的安全机制已处理该场景（ORM 参数化、模板自动转义、全局 CSRF Token、框架级路由过滤等）

### SQL / NoSQL / LDAP 注入 — 必要条件

1. **输入可控**：用户输入能直接或间接到达拼接点
2. **无预编译 / 参数化**：查询用字符串拼接 / `fmt.Sprintf` / `f-string` / `%s` 动态构造，而非 `?` 占位符 / `Prepare` / ORM 参数化查询
3. **无有效过滤或过滤可绕过**：无过滤直接拼接；或黑名单缺关键字、编码绕过（`%2527` / `0x27`）、大小写绕过、内联注释绕过
4. **作为代码执行而非数据**：用户输入拼到结构部分（关键字、表名、列名、ORDER BY / LIMIT 等不可参数化位置），而非作为数据值被参数化传入
5. **执行路径可达**：查询方法被路由 Handler 调用，中间无提前 return / 权限拦截阻断

常见误报：ORM `.Where("field = ?", userInput)` 参数化 → 误报；框架自动预编译 → 误报；输入经严格白名单（只能是整数 ID）→ 误报；`if debug_mode` 分支内生产不执行 → 误报。

### RCE（命令注入 / 代码执行）— 必要条件

1. **输入可控**：用户输入到达命令/代码执行函数的参数
2. **无命令级防护**：无 `shell=False` / 无 `--` 分隔 / 无白名单 / 无输入清洗
3. **可构造有效载荷**：能注入 `; | && $() `` ` 等分隔/替换语法，或反序列化链可控、模板沙箱可逃逸
4. **执行环境可达**：不在被注释代码、未启用功能分支或受限环境中

常见误报：命令参数全部硬编码 → 误报；`subprocess.run([...], shell=False)` 列表传参 → 安全模式 → 误报；反序列化标了 `allowedClasses` → 误报；`eval` 输入全由常量/配置决定 → 误报。

### 文件上传 — 必要条件

1. **文件内容可控**：用户能控制上传文件完整内容
2. **校验缺失或可绕过**：无校验 / 黑名单不全 / 仅前端校验 / MIME 可伪造 / 文件头可伪造
3. **上传路径可达且可直访**：上传目录可通过 URL 直接访问（或能路径遍历移到可直访目录）
4. **服务端可执行**：服务器允许执行上传类型（`.php` / `.jsp` / `.aspx`），或可利用解析漏洞（`.php.jpg` / `.php%00.jpg`）

常见误报：上传到 OSS / S3 服务端不执行 → 降级信息类非 RCE；仅允许图片且校验了文件头（`FF D8` / `89 50 4E 47`）无绕过 → 误报；上传目录不可直访仅 API 下载 → 无直接执行风险。

### 路径遍历 / 任意文件读取 — 必要条件

1. **文件路径可控**：用户输入参与构建读取/写入路径
2. **无路径规范化或可绕过**：未用 `filepath.Clean` / `os.path.realpath` / `Path.normalize` 等，或规范化后仍可穿越（`....//` 绕过）
3. **穿越成功**：能构造 `../` 或绝对路径跳出目标目录
4. **目标文件有内容价值**：读取文件含敏感信息，或写入路径可致代码执行

### 未授权访问 — 必要条件

1. **端点未被认证中间件保护**：路由不在白名单外、无全局中间件拦截、无 Handler 内鉴权逻辑
2. **非公开接口**：返回的数据/操作不是设计上对匿名用户开放的（健康检查、公开 API 文档不算）
3. **返回敏感数据或执行敏感操作**：仅返回 `{"status":"ok"}` 不算未授权漏洞

常见误报：设计上公开的端点（登录、注册、健康检查、公开文档）→ 误报；Handler 内有鉴权逻辑 → 误报；仅能获取低敏公开字段（头像 URL、昵称）→ 降级 low 或误报。

### 越权（IDOR / 水平 / 垂直）— 必要条件

1. **资源 ID 来源是客户端**：操作的资源 ID 直接来自请求参数，而非从 Token/Session 提取
2. **无归属校验**：服务端未校验该资源是否属于当前登录用户
3. **越权操作有实际影响**：能读取/修改/删除他人敏感数据
4. **攻击者能枚举 ID**：资源 ID 可猜测（自增整数、UUID 无速率限制可爆破）

### XSS — 必要条件

1. **用户输入进入输出**：用户输入嵌入到 HTTP 响应 HTML 中
2. **无 HTML 转义或转义可绕过**：模板引擎未自动转义 / 后端未 `html.EscapeString` / 前端用 `innerHTML` / `v-html` 等危险 API
3. **输出上下文允许执行脚本**：输出在 `<script>` 标签内、事件属性中、或 HTML 标签属性外（不在 `<textarea>` / `<style>` 等非执行上下文）
4. **CSP 未阻断**：Content-Security-Policy 未严格禁止 inline script

常见误报：模板引擎默认转义（Jinja2 `autoescape=True`）→ 误报；输出在 `<textarea>` 内浏览器不解析 HTML → 误报；输入经后端过滤库（`bleach` / DOMPurify 服务端版）无已知绕过 → 误报。

### SSRF — 必要条件

1. **URL 可控**：用户输入决定出站 HTTP 请求目标地址
2. **无 URL 校验或可绕过**：未限目标域名/IP / 黑名单可绕过（`127.0.0.1` → `0177.0.0.1` / `[::1]` / `127.1` / DNS Rebinding）
3. **出站请求实际执行**：不是注释或条件未满足分支
4. **内网/云元数据可达**：从服务器网络位置能访问内网服务或云元数据端点（`169.254.169.254`）

### 硬编码密钥 / 凭证泄露 — 必要条件

1. **是真实凭证而非示例/占位符**：不是 `your-api-key-here` / `CHANGE_ME` / `xxx` / `test` / `placeholder`
2. **凭证有效或可能有效**：格式符合真实凭证特征（JWT 密钥有足够长度和熵、数据库密码非空非默认）
3. **存在于版本控制代码/配置**：非 `.env.example` / `config.example.yaml`

常见误报：`password: changeme` / `secret: your-secret-key` 明显占位符 → 误报；`.env.example` 示例值 → 误报；测试文件 `test_password = "test123"` → 误报；密钥长度极短（<8 字符）且无服务使用证据 → 可能误报。

### 过滤判定规则

- **全部必要条件满足** → 保留，进入定级复核
- **缺少任一必要条件** → 标误报（drop），驳回原因对照必要条件清单写明缺哪条、代码证据是什么
- **部分条件不确定**（代码证据不足以判断）→ 保留但降 `confidence` 为 `suspected`，在复核备注说明不确定点

## 2. 跨域去重

对所有 findings 按 `(file_path, line_number, vuln_type_category, sink/route/title 语义)` 聚类：

- `vuln_type_category` 是粗类别：rce / injection / xss / auth / business / file / config
- 只有同一位置 + 同一粗类别 + 同一 sink/route/漏洞语义时才合并为一条，保留**最详细的描述**
- 同一行可能同时承载不同数据源或不同 sink（同一处理函数对不同数据库的查询），不得因行号相同就合并
- 不同域提供了不同视角的利用链 → **合并 call_chain**

## 3. 定级复核与预期结果补全（**必须执行**）

对每个最终保留的 finding 重新评估 `severity`，输出 `severity_reason` 与 `expected_result`（定级原则见 [finding-schema.md](finding-schema.md)）。

严禁按漏洞类型机械套高危。只读查看、普通低敏字段枚举，没有证明可修改数据、接管账号、泄露凭证/密钥、批量导出或组成攻击链，通常只能 `low`；无认证/越权/可枚举场景下泄露手机号、邮箱、身份证、地址等个人信息，最低 `medium`；泄露密码、Token、Cookie、密钥等凭证，最低 `high`。定为 `medium/high` 必须在 `severity_reason` 列出具体证据。

`expected_result` 必须是与 `poc` 对应的 HTTP Response 预期，包含状态行、关键响应头、关键 JSON/HTML/错误字段或数据变化，不要只写"成功"或纯文字结论。

## 4. 覆盖缺口审查

对比 Phase 1 架构摘要里的攻击面（路由清单、中间件、数据源、用户输入入口）与 Phase 2 实际产出 findings 覆盖了哪些攻击面。输出未审计或审计不充分的攻击面列表（写入对话总结的「缺口」一行）。

## 5. 组合漏洞链分析（**必须在前 4 步完成后执行**）

即使每个独立漏洞看起来普通，组合后可能形成致命攻击链。**至少尝试识别 1-3 条**；确实没有可组合的，明确说明原因（写入报告攻击链视图与对话总结）。

常见组合模式：

- 未授权 + RCE/注入 = 远程代码执行
- 未授权注册 + 角色字段可控 = 直接拿管理员权限
- SSRF + 内网服务暴露 = 内网渗透
- SSRF + 云元数据服务 = 云凭证窃取
- 信息泄露（密钥/Token）+ 越权 = 数据接管
- 认证绕过 + 任意越权 = 账号接管
- XSS + CSRF + 越权操作 = 单击劫持管理员
- 配置错误（CORS/调试模式/弱密码）+ 任何漏洞 = 利用难度降低
- JWT 密钥为空 + 任意端点 = 任意身份伪造

每条攻击链描述：步骤序列（每步关联具体 finding）/ 组合后严重性（必须高于单个漏洞）/ 真实可达性判断 / 攻击场景（攻击者角色、已知什么、最终能做什么）。

## 复核结果怎么写进报告

复核不再有 submit 工具 —— 决策直接落到报告 HTML 上：

- **keep 且调整 severity/confidence**：编辑对应卡片 —— 改 `data-sev` 与 `vuln-{severity}` 类名、sev-tag 文本；`confidence=suspected` 时加 `data-confidence="suspected"` 与疑似标签
- **keep 且补 severity_reason / expected_result**：编辑卡片的「定级评判」reason-box 与「预期响应」expected-response-code
- **drop（误报）**：把该卡片**移动**到误报视图（`#fpView`），改 `data-fid` 为 `FP-N`，加 `vuln-fp` 类、`sev-fp` 标签、原等级划线标签、在 `.fp-reason-block` 写驳回原因（对照必要条件清单缺哪条）
- **merge**：保留主卡片，删除被合并的次要卡片；如 call_chain 不同视角，把链路合并进主卡片
- **attack_chain**：每条链一个卡片插入 `#chainsView` 锚点前，`data-fid` 为 `CHAIN-N`，按模板攻击链结构写
- **无误报**：删除 `#fpView` 视图及其标签按钮
- **无可组合攻击链**：在 `#chainsView` 写明"无可组合链"及原因

卡片写法与 HTML 转义规则见 SKILL.md「报告」一节。

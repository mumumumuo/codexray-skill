# 文件操作安全审计

> **风险等级**：🟠 严重 — 可导致 RCE / 敏感数据泄露
> **域 ID**：`file`

## 审计范围

- 任意文件上传（无类型校验、黑名单绕过、解析漏洞）
- 任意文件下载/读取（路径可控、协议可控）
- 路径遍历（`../`、绝对路径、URL 编码绕过、Unicode 绕过）
- 文件包含漏洞（LFI / RFI）
- 危险的归档解压（zip slip、tar slip）

## 任务要求

- 找到所有文件上传接口，**详细分析文件类型校验方式**：
  - 白名单（安全） vs 黑名单（危险） vs 无校验（极危）
  - Content-Type 校验 vs 文件头校验 vs 扩展名校验
  - 是否存在解析绕过（如 `.php.jpg`、`.php5`、`shell.php%00.jpg`）
- 找到所有文件下载/读取接口，检查路径遍历
- 识别路径拼接操作：`os.path.join` / `Path.resolve` / `filepath.Join` 等是否对用户输入做了规范化
- 检查归档解压代码（zipfile、tarfile）是否过滤了路径穿越
- 枚举所有文件相关攻击端点
- 生成每个端点的完整 HTTP 攻击数据包（注意 multipart 格式）

## 全面性要求

- **端点完全枚举**：所有上传/下载/读取端点必须独立列出
- **校验方式完整披露**：报告中必须明确该接口采用了什么校验、如何绕过

## 越权分析要求

- **认证状态**：明确标注「鉴权」或「未授权」
- **越权风险**：是否可访问其他用户的文件
- **权限要求**：触发漏洞所需的最小权限

## 判定纪律

- 上传到 OSS / S3 等外部存储、服务端不执行 → 降级信息类，非 RCE
- 仅允许图片且校验了文件头（`FF D8` / `89 50 4E 47`）、无绕过路径 → 不是漏洞
- 上传目录不可直访、仅通过 API 下载 → 无直接执行风险
- 路径用了 `filepath.Clean` / `os.path.realpath` / `Path.normalize` 且穿越后仍被限制在目标目录 → 安全

## 边界

任意文件上传 / 任意文件下载读取 / 路径遍历 / 文件包含 / 危险归档解压归本域。

以下类型**绝对不要**输出 finding（见 [domain-boundaries.md](../domain-boundaries.md)）：

- 上传后服务端对文件内容做 eval/反序列化导致 RCE → `rce`（校验缺陷本身归本域）
- 业务层未校验用户输入的 URL 触发 SSRF → `business`
- 硬编码的文件存储凭证（OSS Key）→ `config`

字段 schema、定级原则、POC 要求见 [finding-schema.md](../finding-schema.md)。

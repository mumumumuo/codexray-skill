# XSS 漏洞全面扫描

> **风险等级**：🟢 中危 — 可导致会话劫持/钓鱼攻击
> **域 ID**：`xss`

## 审计范围

- **反射型 XSS**：用户输入直接回显到响应
- **存储型 XSS**：用户输入存入数据库后再渲染
- **DOM 型 XSS**：前端 JS 直接将用户输入插入 DOM

## 任务要求

- 识别所有用户输入输出点
- 分析前端渲染机制和过滤方法：
  - 模板引擎是否默认 HTML 转义（如 Jinja2 默认开启 / 关闭 autoescape）
  - 后端是否在写入前过滤了 `< > & " '`
  - 是否使用 `innerHTML` / `v-html` / `dangerouslySetInnerHTML` 直接插入用户输入
  - CSP 配置是否完整
- 检查所有数据存储和检索点（存储型 XSS 的注入点 + 输出点都要审）
- **过滤方法实现逻辑分析**：如果项目实现了自定义 XSS 过滤函数，详细分析是否可绕过：
  - 标签黑名单是否完整
  - 事件属性是否过滤（onerror、onload 等）
  - 编码绕过（HTML 实体、URL 编码、Unicode）
  - 嵌套 / 大小写绕过
- 枚举所有可触发 XSS 的 URL 和参数
- 提供完整的攻击 HTTP 数据包

## 全面性要求

- **存储型 XSS** 必须同时报告**注入点端点** + **输出点端点**
- **端点完全枚举**：所有可触发的端点不得合并
- **参数全覆盖**：同一端点不同参数分别报告

## 越权分析要求

- **认证状态**：明确标注「鉴权」或「未授权」
- **权限要求**：触发漏洞所需的最小权限
- **影响用户**：自身 / 其他用户 / 管理员

## 判定纪律

- 模板引擎默认转义 HTML（Jinja2 默认 `autoescape=True`）→ 不是漏洞
- 输出在 `<textarea>` 内、浏览器不解析 HTML → 不是漏洞
- 输入经后端 HTML 过滤库（`bleach` / DOMPurify 服务端版）且无已知绕过 → 不是漏洞
- 输出上下文不允许脚本执行（`<style>`、HTML 注释内）→ 不是漏洞
- 严格 CSP 禁止 inline script → 利用受阻，降级或说明

## 边界

反射型 / 存储型 / DOM 型 XSS 归本域。

以下类型**绝对不要**输出 finding（见 [domain-boundaries.md](../domain-boundaries.md)）：

- 模板注入导致 RCE（可执行任意代码）→ `rce`
- 越权读取他人数据（即便其中含可注入字段）→ `auth`
- 错误堆栈回显 / Swagger 暴露 → `config`

字段 schema、定级原则、POC 要求见 [finding-schema.md](../finding-schema.md)。
